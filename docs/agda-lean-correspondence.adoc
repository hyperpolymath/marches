= Agda–Lean statement correspondence
:revdate: 2026-11-16

The record that `hyperpolymath/standards` `3-practice/PROOF-POLICY.adoc` §2.2
asks for, group by group. It covers each theorem whose Agda source is in
`proofs/agda` and whose Lean leg is in `Marches/`. For each pair it gives the
exact propositions, their assumptions, their type and universe discipline and
how they were compared. Revisions, checkers, invocations and results are in
`PROOF-STATUS.adoc`. A successful check in each prover does not on its own
show that both proved the same proposition. This page is that separate
argument.

*Method.* The comparison was made by reading. Definitions were compared field
by field and theorems binder by binder, against the Lean files at the commit
named in `PROOF-STATUS.adoc`. No mechanical bridge links the two: there is no
Dedukti round trip, and the Lean leg was not transported. Lean's names are in
snake case and Agda's in kebab case, because an underscore in an Agda name
marks a mixfix argument.

*Route of the Lean leg:* `re-proved`. The Lean development was written by hand
from 2026-07, before the Agda source existed. It was not transported from the
Agda proof.

|`Basic.run A`

|The same two equations: `run A [] a = a` and

|`Prelude.¬_`, `Prelude.⊥`
|`Not`, `False`
|`¬ P = P → ⊥`, where `⊥` is a data type with no constructors. Lean's

|`Prelude._⊎_`

|A sum with two injections. In Agda it is a type, so it is proof-relevant;

The hypotheses are the same in both: one path algebra and its strictness.
Neither side adds an assumption, a typeclass or a section variable. Lean
reports no axioms for any of the four theorems (`#print axioms`), and the Agda
gate finds no postulate in the import cone outside the prover's own level
primitives.

=== Residual assumptions

R1. *Propositions as types.* Agda's `better` and `_⊎_` are `Set`-valued and
proof-relevant. Lean's are `Prop`-valued and proof-irrelevant. A Lean path
algebra gives an Agda one when each proposition is read as a type, and read
at that algebra each Agda statement is the Lean statement. So the Agda
statements quantify over at least the Lean algebras. No statement here
compares two proofs of `better`, or quantifies over `Prop`, so the
difference cannot change the truth of a statement. This is an argument made
by reading. It is not a checked bridge.

R2. *Equality.* Lean's `Eq` has proof irrelevance by definition. Agda is run
without K, so its `_≡_` does not. The statements use equality only in
`run-le` (as a disjunct) and in `no-return` (under a negation), and never
compare two equality proofs, so K is not needed to state them. The Agda
proofs use only J. Neither side needs the other's equality principles.

R3. *Kernels.* The legs are independent kernel results: Agda 2.7.0.1 checked
the Agda source and Lean 4.35.0 checked the Lean source. Each prover's own
kernel is trusted. Agda's trusted base in this cone is `Agda.Primitive`'s
`Level`, `lzero`, `lsuc` and `_⊔_`, each bound by its `BUILTIN` pragma.

=== Negative controls

`tests/reject-agda/FreewheelReturns.agda` gives the free-wheeling algebra:
one signature, extension the identity, no preference. It claims `no-return`
for that algebra, and the gate requires Agda to refuse it. So the strictness
hypothesis of `no-return` is load-bearing, as falsifier F2 is on the Lean side
(`Marches/Freewheel.lean`). `tests/reject-agda/UsesK.agda` proves K. Its pragma
sets `--safe` alone, so the file checks under Agda's defaults, which have K.
Its refusal by the gate therefore shows that the gate's own command line runs
with `--without-K`.

=== Residual assumption R4

R4. *Index matching under `--cubical-compatible`.* For `ctrans`, `cirrefl`
and `trace-worsens`, Agda warns `UnsupportedIndexedMatch`: the clauses rely
on constructor injectivity (of `inA`, `inB` and `_∷_`), which Cubical Agda
cannot yet compute along transports. The warning is about how these
functions compute when applied to transports. It is not about whether their
types are inhabited, and Agda accepts the terms under the canonical flags.
The gate keeps the warnings visible rather than silencing them
(januskey does the same).

=== Negative control

`tests/reject-agda/BackCross.agda` offers the `cross` constructor for a step
that starts in B, and the gate requires Agda to refuse it
(`inA _ != inB x of type Pos A B`). So `no-back-cross` states a fact about
the judgment, not a vacuous negation.
